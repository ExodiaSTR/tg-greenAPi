# Test — React-чат для Telegram через GREEN-API

Тестовое задание: подключение к Telegram-инстансу, создание личного чата по номеру телефона, отправка и получение текстовых сообщений. React + TypeScript + Vite. По уточнению пользователя реализован только Telegram.

## Локальный запуск

Нужен Node.js 22.12+ (проверено на 24.12.0) и npm.

```sh
cd /Users/exodia/workspace/reusable-agent-kit/Test
npm ci
npm run dev
```

Откройте адрес, который выведет Vite (обычно http://127.0.0.1:5173).

```sh
npm test
npm run build
npm run preview
```

`dist/` — production build. Для размещения достаточно статического HTTPS-хостинга. GitHub и публикация не выполнялись, письмо работодателю не отправлялось.

## Подготовка GREEN-API

1. Создайте **Telegram-инстанс** в личном кабинете GREEN-API и авторизуйте его по официальной инструкции сервиса. Это не Telegram Bot API.
2. Возьмите `apiUrl`, `idInstance`, `apiTokenInstance` из кабинета. Введите их в форме. Предзаполненный apiUrl — пример, замените его на адрес своего инстанса.
3. Настройте HTTP-получение уведомлений: `webhookUrl` должен быть пустым, входящие сообщения должны быть включены. Для обновления статусов включите уведомления об исходящих сообщениях/статусах. Приложение не меняет настройки инстанса автоматически.
4. Используйте выделенный тестовый инстанс и один открытый клиент: HTTP-очередь общая для инстанса, приложение подтверждает полученные события через DeleteNotification, включая неподдерживаемые медиа/сервисные события. Это удаляет уведомление из очереди, а не сообщение в Telegram.
5. Введите настоящий номер получателя с кодом страны, создайте чат, отправьте текст. Ответьте с Telegram получателя — текст появится в переписке. Получатель должен быть доступен по номеру с учётом настроек Telegram.

## Поведение и границы

- `getStateInstance` проверяет авторизацию, `getContactInfo` сопоставляет телефон с числовым Telegram chatId. `sendMessage` отправляет текст до 4096 символов.
- `receiveNotification` вызывается последовательно с long polling; `deleteNotification` — после проверки и обработки. Повторы сообщений устраняются по паре chatId + idMessage.
- Ответ sendMessage означает принятие в очередь, поэтому начальная метка «В очереди» не обещает доставку. При наличии статусных уведомлений метка обновляется.
- При ошибке получения видна причина и доступно возобновление. Нет автоматических повторных отправок: сетевой сбой может скрывать успешно принятый запрос. Черновик сохранён; перед повтором проверьте Telegram.
- Нет офлайн-очереди, вложений, поиска, загрузки прежней истории и серверного хранения. Новые события доступны, пока открыт клиент. Чаты, черновики, токен и полученные сообщения хранятся **только в памяти**: перезагрузка/выход очищают их. После подтверждения очереди приложение не восстановит их без отдельной загрузки истории; оригиналы остаются в Telegram.
- Запросы идут из браузера непосредственно в GREEN-API по HTTPS. Токен неизбежно виден владельцу вкладки в DevTools и участвует в URL по контракту сервиса; в localStorage, исходниках и логах приложение его не сохраняет. Сообщения React выводит как текст, без HTML.
- Интерфейс на русском, международные номера, локальная временная зона устройства. Отдельные мобильные приложения и другие языки не входят в тестовое.
- Две колонки на широком экране, список/чат с возвратом на узком. Подписи полей, клавиатурный фокус, live-сообщения и кнопки от 44px. Проверка со скринридером и полный аудит WCAG не выполнены.
