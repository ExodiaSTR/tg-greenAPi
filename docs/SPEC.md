# Требования и решения

Источник: https://drive.google.com/file/d/1Ut39kkIs0QK-swnCsIPJc6pNqVIVGOD2/view — «Тестовое задание на должность — Фронтенд разработчик React (v5).pdf», прочитан 02.10.2026.

PDF требует минимальный React-интерфейс для отправки и получения текста через GREEN-API. Основной мессенджер MAX; Telegram и WhatsApp прямо разрешены как альтернативы. Ожидаемый путь: ввод idInstance/apiTokenInstance → создание чата по номеру → отправка текста → ответ получателя в мессенджере → отображение ответа.

Пользователь: «работай с телеграм», затем «сделай только для телеграм». Принято: только Telegram, без MAX/WhatsApp. Сохранить проект в Test внутри reusable-agent-kit. Запрос не включает отправку результата работодателю, публикацию, создание аккаунта, загрузку резюме или использование личной переписки.

Внешний вид: PDF ссылается на web.max.ru, который не загрузился в доступном браузере. После сообщения о пробеле пользователь указал делать только Telegram. Реализован простой Telegram-чат, точное соответствие MAX или Telegram не заявлено: editable-макет и токены отсутствуют. Это ограничение визуальной проверки, не доказательство совпадения.

Критерии до реализации: production build проходит, runtime-проверка входящих контрактов, тест телефонного адреса/числового ID, отправки/получения/подтверждения, дубликатов, ошибок без утечки токена, сохранения черновика и очистки при выходе. Живой путь проверяется отдельно с тестовым инстансом и вторым Telegram-аккаунтом.

Политика данных: вкладка принадлежит одному инстансу; выход отменяет его запросы и очищает память. Нет долговременной истории/офлайн-синхронизации. Сервер GREEN-API определяет принятие и доставку; отказ и неизвестный результат видимы. При необходимости истории следующий рубеж — явная загрузка официальной истории или утверждённое защищённое хранение, а не добавление localStorage с токеном.

Специалисты: Product, Design, Domain и Frontend применены через чтение профилей основным исполнителем; QA выполнена отдельным агентом. Область Domain — личная текстовая переписка с авторизованным Telegram-инстансом. Корневой PROJECT_CONTEXT.md остаётся шаблоном набора правил; факты этого отдельного задания находятся здесь, канонический статус — STATUS.md.

Локальный дизайн-источник — src/App.tsx и src/styles.css, одни общие исходники входа и чата. Состояния: вход/проверка/ошибка, пустой список/чат, активный чат, отправка/очередь/статус/ошибка, получение/остановлено/повтор, отсутствие сети. Hover, focus, pressed, disabled заданы в CSS. Анимация не добавлена; reduced-motion поддержан. Чат имеет внутреннюю прокрутку для непрерывной переписки; остальные формы не скрыты за прокруткой компонентов.
